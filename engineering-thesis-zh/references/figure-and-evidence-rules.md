# Figure And Evidence Rules

Use this reference to plan figures, tables, screenshots, and claim evidence.

## Evidence Map

For each chapter, maintain a table with:

- Claim.
- Evidence source.
- Evidence type: code, config, CSV, test, figure, screenshot, document, user confirmation.
- Allowed wording.
- Forbidden wording.

## Figure Types

Allowed engineering thesis figures:

- system architecture diagram
- module structure diagram
- process flow diagram
- sequence diagram
- algorithm flowchart
- simulation event flow
- state transition diagram
- E-R diagram
- result chart from real CSV/output
- real runtime screenshot

## Figure Rules

- Use plain engineering style: white background, black/gray lines, clear labels.
- Do not use decorative icons or infographic styling.
- Every figure must correspond to code, data, or a documented process.
- Captions should state what the figure shows, not make unsupported conclusions.

## Table Rules

- Tables should summarize parameters, metrics, comparisons, test cases, or database fields.
- Do not create performance tables without measured results.
- Keep units and parameter meanings explicit.
